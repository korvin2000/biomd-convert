# biomd-convert — project constitution

Binding rules for **every** session in this repository. Durable rules only: measured state lives in
`biomd-convert/CONVERTER-PROGRESS.md`, precise open-defect state in `analyze/defects.json`. Do not
duplicate either here.

**Communicate with the user in English.** Not German. Technical terms and code identifiers keep their
original form.

A session that has lost its context re-orients from this file, `CONVERTER-PROGRESS.md`,
`analyze/defects.json` and `TaskList`.

| what | where |
|---|---|
| current refinement campaign brief | `analyze/REFINE-CONVERTER.prompt.md` |
| durable measured state, what remains, what is unreachable | `biomd-convert/CONVERTER-PROGRESS.md` |
| precise open-defect state (generated by L2) | `analyze/defects.json` |

---

## 1. What this is

A deterministic-first compiler from legacy HTML to BioMD Lite 1.6. The corpus is ~1000 Russian-language
biographies of guitarists and composers, authored in 1998-era Microsoft FrontPage: bloated, frequently
malformed, table-based layout, presentational markup, no semantics. Thirteen pages have hand-made
reference conversions in `biomd-convert/fixtures/`.

Those thirteen are **evidence, not the target**. The product is a rule system that generalizes to the other
~987 pages and to any structurally similar corpus, plus an evaluation apparatus that localizes defects
precisely enough to act on. Both halves are deliverables.

Fidelity means three things at once: conformance to `Biography-Markup.md` under the target profile;
structural and visual equivalence to the references — layout intent, not pixels; and no loss or invention of
content. Moving one while breaking another is a regression.

Environment: Windows, Node ≥ 22, TypeScript/ESM, vitest, parse5, optional Playwright (Chromium measurement),
zod, commander. PowerShell and Bash are both available.

```bash
cd biomd-convert && npm run build && npm test
```
```bash
cd biomd-convert && sh bench/run.sh
```
```bash
cd biomd-convert && node dist/cli/index.js diff -c bench/biomd.config.json --json ../analyze/defects.json
```
```bash
cd biomd-convert && npm run biomd -- inspect fixtures/html/segovia.htm
```

## 2. Ground truth, highest precedence first

1. **`Biography-Markup.md`** — normative BioMD Lite 1.6 syntax, and §16.3 (no invented content).
2. **`biomd-convert/fixtures/html/*.htm` ↔ `fixtures/out/*.bio.md`** — 13 hand-made pairs. Normative for
   every judgement the spec leaves open. Read them as evidence of intent.
3. **`analyze/analyze.md`** (Russian, per-page complaints) + **`analyze/design.png`** (green frames =
   convert, red = chrome to drop) + `analyze/snapshot_*.png`. The only record of *human* quality judgement.
4. **`html-to-biomd_guide.md`, `html-to-biomd_ext_guide.md`** — the manual procedure behind the references.
   Advisory and possibly stale: where a guide contradicts `fixtures/out/`, the reference wins — and say so.
5. **`biomd-convert/CONVERTER-PROGRESS.md`** — current measured state. Verify, don't trust.
6. **`CONVERTER-ASSESSMENT.md`, `htm-to-md_utility_plan.md`, `how_to_fix_table_parsing_and_reconstruction.md`**
   — historical. PROGRESS §3 records where the assessment was measurably wrong; that pattern repeats.

## 3. Invariants

The only hard limits. Everything not forbidden here is available, including large architectural change.

1. **Reference integrity.** Never edit `fixtures/html/`, `fixtures/out/`, or `analyze/*.md` / `analyze/*.png`.
2. **Metric integrity.** Never tune `src/eval/score.ts`, or any instrument built here, to move a number.
   Instruments change only to become *more truthful*, in isolated declared steps, with both sides re-baselined.
3. **No instrument may become the objective.** Scalar score, structural diff, visual diff, LLM judge — each
   is a defect detector, never a thing to maximize. On catching yourself optimizing an instrument's output
   rather than the conversion: stop and say so.
4. **No invented content** (§16.3). Where a reference contains text absent from the source, record it as an
   unreachable ceiling. Never close a gap by fabricating. **§16.3 constrains text, not layout** — wrapping
   existing text in a directive, splitting a lane, drawing a separator or reading a size off geometry
   invents nothing and is always actionable.
5. **No literals law.** No corpus-specific string, class, id, filename or title inside a detector. Lexical
   knowledge (bullet glyphs, label vocabularies, border palettes) lives in documented, language-tagged data
   files, and every rule consulting one degrades gracefully when the list does not match. A detector must
   never be able to name a document.
6. **Determinism.** Same input + `--replay` ⇒ byte-identical output. Diagnostic tools are deterministic too,
   or they are labelled non-deterministic and never gate a decision alone.
7. **Honest measurement.** Report no number not measured, no completion not verified. A crashed conversion
   invalidates that run's measurements — say so rather than reporting the remainder.

## 4. Evaluation is a ladder, not a number

A level is only meaningful when the one above it is clean.

**L0 — Gate.** Every change. `npm test`; the mutation suite (§5); zero FAILED conversions in `corpus run`;
`biomd validate` errors not increased; `biomd-ast/read()` warnings on produced output = 0; conservation
ledger clean. Red L0 invalidates everything below.

**L1 — Scalar tripwire.** Every change. `sh bench/run.sh`. Deliberately demoted: a *silent-regression
detector for areas not currently under examination*. An unchanged score is not evidence that nothing
changed — `score.ts` averages seven multiset F1 axes and is blind to every directive property, every link
label, every cell coordinate, block order, hard breaks, emphasis and typography.

**The legitimate L1 target is ≈ 98 %, not 100 %.** The remaining ~2 % is reference editorializing that
§16.3 forbids closing: invented headings, copyedited prose, `segovia`'s deleted MP3 track table. Treat
≈ 98 % as the acceptance ceiling for the project as a whole; day-to-day, L1 stays a tripwire and never a
per-change objective (invariant 3).

**L2 — Structural adjudication. The primary instrument. Built.** `src/eval/blocks.ts`,
`src/eval/structdiff.ts`, `src/eval/triage.ts`, `src/eval/rollup.ts`; contracts in
`src/eval/structdiff.test.ts`; surfaced as `biomd diff`. Diagnostic-only — `convert-core` must never import
it. Output is *N localized findings*, never an average, compared at full resolution: directive name and
every property value; heading level, order and nesting; table cell **coordinates** and column alignment;
link label ↔ target pairing; image `alt` ↔ `caption` ↔ `size` ↔ `align` ↔ `link` binding; list type and
nesting depth; separators; blank-line and hard-break structure; emphasis spans; inline typography; entity
decoding; hyphenation artifacts; whitespace. A finding that cannot be acted on directly has a class that is
not yet precise enough — refine the class, not the tolerance. Held to **identity** (same document both
sides ⇒ zero findings) and **determinism**.

**L3 — Rendered and geometric adjudication. NOT YET BUILT — see PROGRESS §7.** Build `tools/render-biomd.ts`
from `Biography-Markup.md`, modelling the target renderer's known quirks (`biomd-ast/read.ts` documents the
`PROPERTY_HEADER_DIRECTIVES` asymmetry and `columns.divider` promoted to a synthetic first column;
`conformance.test.ts` asserts them). Diagnostic-only; the converter must never import it. **Invariant: both
`.bio.md` sides render through identical code** — the same file twice must produce byte-identical output.
Then compare three ways in the built-in browser over HTTP (`.claude/launch.json` declares both servers):
source `.htm` ↔ produced `.bio.md` ↔ reference `.bio.md`. `read_page` for structure; `javascript_tool` for
`getBoundingClientRect` / `getComputedStyle`; `computer` to see it; `resize_window` to prove a lane is not
viewport-dependent. The question only L3 can answer — is the produced layout *visually equal to or better
than* the source — is the actual project goal.

Three verified corpus facts that shape L3 work:

- **Presentational attributes lie.** On `pavlov_azancheev.htm`, `align="center"` appears on `p.t8` (17×),
  `p.t` (16×), `p.t1`, `p.st` and `p.lt` — every one computing to `justify`. Only `p.t3` (3×) is centred.
- **Computed `text-align` is not always the keyword you expect.** Chromium returns `-webkit-center` /
  `-webkit-left` for elements centred by an ancestor's `align` attribute. An exact `=== "center"` comparison
  under-detects. `prominence.ts:132` and `structure.ts:1809` handle this; **`prominence.ts:138` and
  `structure.ts:1437` do not** — a live inconsistency, not a style preference.
- **No asset tree exists.** Every referenced image, PDF and MP3 404s. Rendered pages show broken images by
  construction — never chase that as a conversion defect.

**L4 — LLM adjudication.** A *judge* pipeline over `src/llm`, strictly separate from production hooks:
**side-blind** (randomize A/B, run both orders, keep only findings stable under the swap);
**localized and schema-validated** (zod; quoted spans from both sides, node path, severity, defect class,
source-backing verdict — a judge returning prose or a score is misconfigured); **strong model**
(`claude-opus-5` via the `deep` slot, not the cheap `fast` model the production hooks use);
**calibrated before trusted** against pages whose defects `analyze/analyze.md` already names, reporting the
agreement rate; **advisory only** — findings are hypotheses to confirm with L2/L3, never ground truth and
never a target.

**L5 — Human record cross-check.** Every complaint in `analyze/analyze.md` and every red/green region in
`design.png` maps to a defect class that is closed, open with an owning cell, or classified unreachable.
When instruments and the human record disagree, **the human record wins and the instrument gets fixed** — a
blind spot found this way is worth more than the defect that revealed it.

**Triage — mandatory, four-way, before any finding becomes work.** The objective is a valid, visually good
BioMD conversion that preserves the source content and reproduces the source's layout intent where that is
useful — *not* byte-agreement with thirteen hand-made files. A produced document may be **better** than its
reference when it is demonstrably clearer, more consistent with `Biography-Markup.md`, and visually equal or
better. Every mismatch therefore gets one of four verdicts, and only the first is work:

1. **`converter-defect`** — the output loses content, violates BioMD, misreads source structure, or produces
   a worse layout. Gets a work cell.
2. **`acceptable-alternative`** — differs from the reference, preserves the intent, visually equal or better.
   Recorded, excluded from targets, never "fixed" toward the reference.
3. **`reference-inconsistency`** — the reference made an unsupported, internally inconsistent or inferior
   editorial choice. Recorded as ceiling. §16.3 forbids closing it.
4. **`ambiguous`** — deterministic evidence cannot decide. L4 judge territory, or a question for the user.

Verdicts 2 and 3 both mean "not a target", and confusing either with 1 is the failure mode that wastes the
most work. Test **both sides against the source**, not only the reference: when the produced side is attested
and the reference side is not, the reference is the thing that moved.

*Layout* structure is always verdict 1 (invariant 4 — wrapping, splitting and separating invent no text).
*Presentational* structure — emphasis spans, hard breaks, inline typography — is **not** layout and must be
decided by attestation like content. Treating the two alike is what made an emphasis span the reference
deleted look like a converter defect.

**Never edit a reference to close a finding.** When a reference looks wrong or inferior *and* the decision
would affect a reusable rule or several documents, put a concise side-by-side to the user and ask which
reading is authoritative. Batch related questions; decide minor local ones yourself.

**The defect ledger — `analyze/defects.json`**, regenerated by L2 and appended to by L3/L4/L5. Per finding:
stable id, class, severity, evidence, node path, both-side line numbers, both-side quoted spans,
source-backing verdict. Per class: instances, documents affected, backing breakdown, rank, example.
**Progress is reported as classes closed and instances remaining per class**, never as an average, with L1
alongside as a tripwire. Rank work by `instances × severity × generality`, where generality = how many
documents and archetypes share the class. Generality is the tiebreaker: a class recurring in six documents
teaches more than a bigger one in a single document.

**Cadence.** L0 + L1 every change · L2 every iteration and corpus-wide before every commit · L3 for every
document touched, all 13 at milestones · L4 batched per iteration, cost-capped · L5 at milestones.

**Folds.** Never tune on all thirteen. With 13 pairs, overfitting is the default outcome and no instrument
announces it. Hold out 3–4 documents while designing a rule; measure them only after the rule and its tests
are written. Rotate the holdout, report both sides. A rule whose holdout behaviour is far weaker than its
development behaviour is a special case in a general rule's clothing — generalize it or drop it.
Generalization beyond the 13 has no reference, so it has a checklist: crashes, validation errors, `read()`
warnings, conservation reports and `review()` escalations must not rise on any input outside the reference
set, including mutation fixtures.

## 5. Rule design for generalization

Every rule added or changed carries a **rule contract**, stated in the test file beside it:

- **Invariant** — the evidence it keys on, expressed without naming a document, class, id or literal:
  geometry, recurrence, containment, ordering, cardinality, typographic role. Prefer *relational* evidence
  ("centred on a page whose prose is not") over absolute thresholds ("width < 400 px").
- **Recurrence requirement** — the same shape must repeat on the page with content between occurrences.
  Every detector that survived here required recurrence; every single-block typographic threshold regressed
  it. This is a design law, not a heuristic.
- **False friend** — the near-identical shape it must *not* fire on. Each family has one: a caption
  resembles a heading, a menu label a section label, a record label a section, a copyright line a signature.
  Name it and test non-firing.
- **Mutation robustness** — a harness deriving variants from existing fixtures, asserting the produced
  **shape** is unchanged under: renamed classes and ids; permuted attribute order; added and removed wrapper
  nesting; dropped or duplicated closing tags; `<font>`/`<b>` swapped for equivalent CSS; Latin labels
  swapped for Cyrillic and back; different viewport widths; different encodings. Assert with L2, not with
  the scalar score.
- **Shape catalog** — a documented catalog of page archetypes (masthead + prose, prose with bound figures,
  discography grid, multi-column media/score table, dated news list, link farm, mixed single→multi→single
  column flow) with entry and exit evidence, and which defect classes each archetype exhibits. New pages map
  onto a known shape or announce themselves as unmapped.
- **Many small passes over one universal rule.** Small passes compose, are individually testable, and fail
  locally. New passes run through `runPass`/`Ledger` so provenance and conservation stay auditable.

**Corpus facts a rule may assume**, because geometry confirms them corpus-wide: content is the centre column
(~½ viewport); page chrome and footer drop; right-hand menus fold into the main flow; most images are
captioned and centred or right-aligned; discographies and score/media lists run 2–5 columns; more than 5
columns, or a page dense with blockquotes, is an anomaly rather than a layout; vertically aligned blocks in a
multi-column region are semantically paired, and splitting such a region into several small tables to
preserve that pairing is legitimate. Original layout is preferred; where geometry cannot be proven, a cleaner
Markdown-native layout of equal quality beats a guessed one.

Content is Russian. Do not "correct" it beyond what the references demonstrably do.

## 6. Rules vs hooks

Rules handle what the source states. Hooks handle only what the source does not state.

Every production hook stays zod-schema-validated, budgeted, cached, replayable and **non-authoritative**: a
hook proposes, a deterministic check accepts or rejects, and the rejection path is tested. Add one only when
both the evidence rules cannot supply *and* the acceptance check that guards it can be named. A hook is also
the right home for judgement that will not generalize into a rule — but it must degrade to sane deterministic
output when disabled, since 1000 pages will not all be escalated.

Keep the production hook path and the L4 judge path strictly separate: different models, different prompts,
different purposes. Adjudicate with LLM off for comparability; measure the LLM-on delta as a separate,
explicitly labelled run. Existing hooks: `table.classify`, `table.records`, `text.segment` (`src/llm/hooks.ts`).

## 7. Instrumentation

- **What the front half saw** — `biomd inspect <file>`; per-job artifacts in
  `my-migration/.biomd-work/<name>-<hash>/`. The `Ledger`'s `review()` entries are the queue of decisions
  the rules gave up on.
- **Corpus-level evidence** — `biomd corpus scan`. Detectors that generalize should be discoverable *there*,
  not per document.
- **HTML structure** — parse5/LADOM queried from a throwaway `node --experimental-strip-types` script, never
  by regexing `.htm`.
- **Text diffing** — `git diff --no-index --word-diff fixtures/out/X.bio.md bench/out/X.bio.md`, as a quick
  look only; L2 is the adjudicator.
- **External knowledge** — `WebSearch` / `WebFetch` for FrontPage-era markup quirks and CSS cascade edge
  cases. Cheaper than a wrong hypothesis.
- Scratch scripts, probes and notes belong in the session scratchpad directory, never in the repo.

---

## 8. Reporting conventions

Report defect classes and instances, not averages. State failures with their output. When something is
blocked, finish everything else and say precisely what is blocked and why.

At milestones, update `CONVERTER-PROGRESS.md` in the style it is already written in — measured numbers, what
was implemented, what remains reachable, what is provably unreachable — plus the shape catalog, the
instrument calibration record and the killed-hypothesis list. Those three are the parts a successor cannot
reconstruct.

---

## 9. Stop conditions

Stop when all of these hold:

- no open `source-backed` defect class above minor severity remains that does not require a hook whose
  acceptance check cannot be defined;
- L0 clean, L1 not regressed and at or near the ≈ 98 % legitimate target, holdout gap small and explained,
  mutation suite passing;
- L3 finds no structural or ordering difference on any of the 13, and judges the produced layout equal to or
  better than the source on each;
- L4, calibrated, opens no new source-backed class across two consecutive rounds;
- every `analyze.md` complaint is closed or classified unreachable with its reason.

Then report: the ceiling and its cause; what would be needed to break it; which rules are expected to hold on
the other ~987 pages and which are expected to break first; and which instrument is trusted least, with the
evidence for that mistrust.
